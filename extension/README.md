# pravq go — Chrome Extension

A ComfyUI-inspired infinite canvas workspace as a Chrome extension (Manifest V3).

## Load the extension (unpacked)

1. Open `chrome://extensions` in Chrome/Edge/Brave
2. Enable **Developer mode** (top-right toggle)
3. Click **Load unpacked**
4. Select the `extension/` folder from this project
5. The pravq go icon appears in your toolbar

## Usage

- **Click the toolbar icon** → opens the canvas in the Chrome Side Panel
- **Open a new tab** → canvas loads as the new-tab page (override)
- **Right-click the icon → Options** → configure backup, tab behavior, privacy

## Features

- Infinite canvas with pan/zoom, snap-to-grid
- 7 node types: Text, Markdown, Rich Text, Group, Label, Media, Search
- ComfyUI-style spaghetti connections
- Privacy Mode (P) — blur all node content
- Keyboard shortcuts overlay (?)
- Undo/Redo (Ctrl+Z / Ctrl+Shift+Z)
- Search palette (Ctrl+K)
- Auto-save + auto-backup (chrome.storage.local)
- Optional remote backup to your own server
- Optional pinned-tab-per-node

## Settings (Options page)

### Auto Backup (Local)
- Enable periodic local backups
- Configurable interval (default: 5 minutes)
- Keeps last 50 backups

### Remote Backup
- Push canvas state to your own server via PUT
- Configurable URL + Bearer auth token
- Configurable interval (default: 30 minutes)
- Optional: push after every edit (debounced 2s)

### Node Tabs
- Open each node in its own pinned tab
- Tab mode: pinned / popup / normal
- Edits sync back to canvas via storage events

### Canvas
- Enable privacy mode on launch

## Architecture

```
extension/
├── manifest.json              # Manifest V3
├── background.js              # Service worker (alarms, backup, messaging)
├── sidepanel.html             # Side panel entry (primary canvas surface)
├── newtab.html                # New-tab override
├── popup.html                 # Toolbar popup (quick actions)
├── options.html               # Settings page
├── entry.jsx                  # Vite entry (renders canvas, patches store)
├── lib/
│   └── storage.js             # chrome.storage.local adapter (+ web fallback)
├── content/                   # Built bundle (generated by Vite)
│   ├── canvas-bundle.js       # React canvas app (~577KB)
│   └── styles.css             # All CSS (~68KB)
└── icons/                     # 16/48/128 px PNGs
```

## Rebuild the bundle

If you change any source in `src/`, rebuild the extension bundle:

```bash
bunx vite build --config vite.extension.config.js
```

This regenerates `extension/content/canvas-bundle.js` and `styles.css`.

## How it works

The same React canvas components power both the web app (`src/`) and the extension. The extension's `entry.jsx` imports the canvas, then patches the Zustand store's `save`/`load`/`backup` methods to use `chrome.storage.local` (via the background service worker) instead of the Next.js API routes. This means:

- **In the extension:** state persists to `chrome.storage.local` (synced across the extension's surfaces)
- **In the web app:** state persists to `/tmp/canvas-data/state.json` via API routes

No server is needed for the extension — everything runs client-side.

## Permissions

| Permission | Why |
|---|---|
| `sidePanel` | Primary canvas surface (Chrome 114+) |
| `storage` | `chrome.storage.local` for canvas state, `chrome.storage.sync` for settings |
| `tabs` | Pinned-tab-per-node feature |
| `alarms` | Periodic auto-backup |
| `unlimitedStorage` | Canvas state can grow large |
| `<all_urls>` | Remote backup + Media node loading external images |

## FAQ / Troubleshooting

**Q: Why is there a "Customize Chrome" footer at the bottom of the New Tab page?**
A: In recent updates, Chrome automatically injects a security footer on any extension that overrides the New Tab Page to prevent malicious hijacking. 
To hide this footer:
1. **Right-click** anywhere on the dark footer bar at the bottom of the new tab.
2. Select **"Hide footer on New Tab page"**. Chrome will remember this preference for your browser.
